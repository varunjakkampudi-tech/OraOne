# Security controls and accepted risks

This page lists the security controls that exist in the code, with the file that implements
each one, and the risks that are accepted or still open. It is a summary for engineers and the
owner. It is not a penetration test or a certification. The threat model and the rules for
reporting a vulnerability are in [SECURITY-MODEL](../security/SECURITY-MODEL.md) and
[SECURITY.md](../../SECURITY.md).

Checked against commit `e6f8237` on branch `feat/product1-launch` by reading the code. Nothing on
this page was tested against the running production stack. Items marked **unverified** need a
check on the server.

## 1. Controls in the code

### Sign-in and sessions

| Control                                                                                                                                                         | Where                                                                                     | Notes                                                               |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| Passwordless email codes. Each code is single-use, lasts 10 minutes and is compared in constant time.                                                           | `backend/app/services/auth_service.py` (`_LOGIN_CODE_TTL_SECONDS`, `hmac.compare_digest`) | A code is deleted after its first successful use.                   |
| Code attempts are limited. After 5 wrong attempts in a window, the code is invalidated.                                                                         | `auth_service.py` (`MAX_CODE_ATTEMPTS = 5`)                                               |                                                                     |
| Access tokens are short-lived HS256 JWTs. The default lifetime is 15 minutes.                                                                                   | `backend/app/core/security.py`, `JWT_ACCESS_TTL_MINUTES`                                  | Signed with `JWT_SECRET_KEY`, which must be at least 32 characters. |
| Refresh tokens rotate on each use. Logout revokes one token and logout-all revokes every token for the user.                                                    | `auth_service.py` (`token_service.rotate`, `revoke`, `revoke_all_for_user`)               |                                                                     |
| Session cookies are httpOnly and SameSite=Lax. They are Secure whenever `ENVIRONMENT` is production-like or unset. The refresh cookie is scoped to `/api/auth`. | `backend/app/core/cookies.py`                                                             |                                                                     |
| Password sign-in for seeded development accounts is off unless `ENVIRONMENT=development` and `ALLOW_DEV_PASSWORD_LOGIN=true`.                                   | `auth_service.py` (`_dev_password_login_allowed`)                                         | The seed script also refuses to run outside development.            |
| The web app keeps no session token in browser storage. `sessionStorage` holds only an admin preview flag.                                                       | `src/routes/admin.tsx`                                                                    | Session state is in the httpOnly cookies.                           |

### Startup and configuration

| Control                                                                                                                                                                                                                                                                            | Where                                                                                                                 | Notes                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| In production-like environments (`production`, `prod`, `staging`), the API refuses to start when required settings are missing. The checks cover the JWT secret, Twilio settings, the Meta app secret and `OPENROUTER_API_KEY`. The error names the settings but not their values. | `backend/app/core/startup_checks.py`                                                                                  | `CORS_ORIGINS` is checked when the middleware is built. |
| CORS origins must be exact `http` or `https` origins. Wildcards, paths, queries and invalid ports are refused.                                                                                                                                                                     | `backend/app/core/cors.py`                                                                                            |                                                         |
| Secrets are never returned in full. The admin API returns a set or not-set flag and, for values of 12 characters or more, the last four characters.                                                                                                                                | `backend/app/core/config_registry.py` (`mask_secret`), `backend/app/services/platform_admin.py` (`secrets_inventory`) | The secret inventory lists 12 names.                    |
| Saved console values are encrypted with a key derived from `INTEGRATIONS_ENCRYPTION_KEY`.                                                                                                                                                                                          | `backend/app/core/crypto.py`                                                                                          | Changing the key makes saved values unreadable.         |
| The admin configuration console is limited to the `super_admin` platform role, requires a reason for every change, and publishes only the drafts an administrator has reviewed. Each refused attempt and each applied change is audited.                                           | `backend/app/api/admin_config/routes.py`, [ADMIN-CONFIG](../guides/ADMIN-CONFIG.md)                                   |                                                         |

### Requests, headers and rate limits

| Control                                                                                                                                                                                                                                                 | Where                                                                     | Notes                                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Client IP addresses from `X-Forwarded-For` are used only when the connection comes from a proxy listed in `TRUSTED_PROXY_IPS`.                                                                                                                          | `backend/app/middleware/rate_limit.py`                                    | An entry that is too broad lets clients fake their IP address. See section 2.                          |
| Rate-limit tiers: sign-in and refresh 10 requests a minute, AI routes 20, webhooks 600 per source IP, other API routes 120.                                                                                                                             | `rate_limit.py` (`TIERS`)                                                 |                                                                                                        |
| The `auth` and `ai` tiers fail closed when the shared store fails.                                                                                                                                                                                      | `rate_limit.py` (`FAIL_CLOSED_TIERS = {"auth", "ai"}`)                    | The webhook and general API tiers fail open. See section 2.                                            |
| The API sends `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, a `Referrer-Policy`, a `Permissions-Policy`, `Cross-Origin-Opener-Policy`, and a strict `Content-Security-Policy` for JSON responses. Swagger paths are exempt.               | `backend/server.py` (`security_headers_mw`)                               |                                                                                                        |
| The Caddy edge sets HSTS, `nosniff`, `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy`, a `Permissions-Policy` that turns off camera, microphone, geolocation, payment, USB, serial and Bluetooth, and a `Content-Security-Policy` for the web app. | `Caddyfile`                                                               | See the CSP risk in section 2.                                                                         |
| Only Caddy publishes ports (80 and 443). The backend, workers, frontend, PostgreSQL and Redis do not publish ports.                                                                                                                                     | `docker-compose.prod.yml`                                                 | Host firewall rules are not in the repository. See [HOSTINGER-DEPLOYMENT](../HOSTINGER-DEPLOYMENT.md). |
| The backend container runs as the non-root user `oraone`. The frontend container runs as `node`.                                                                                                                                                        | `backend/Dockerfile` (`USER oraone`), `frontend.Dockerfile` (`USER node`) |                                                                                                        |

### Tenant isolation and authorization

| Control                                                                                                   | Where                                                                                                                                        | Notes                                               |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| Data access is scoped to an organization. About 90 service and route modules reference `organization_id`. | `backend/app/services`, `backend/app/api`                                                                                                    | A query-by-query audit was not part of this review. |
| Platform roles and organization roles are checked on the server for each privileged route.                | `backend/app/api/rbac/routes.py`, `backend/app/services/authorization.py`                                                                    |                                                     |
| Cross-tenant and permission behaviour is tested.                                                          | `backend/tests/test_phase5_org_isolation.py`, `test_product_tenant_security.py`, `test_platform_rbac.py`, `test_security_authz_hardening.py` |                                                     |

### Inbound provider calls

| Control                                                                                                                                                               | Where                                                                           | Notes                                                              |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| Twilio requests are verified with `X-Twilio-Signature` against the public URL in `PUBLIC_API_BASE_URL`.                                                               | `backend/app/services/channels/adapters.py` (`RequestValidator`)                | Calls without a valid signature are refused.                       |
| Meta webhooks are verified with `X-Hub-Signature-256` (HMAC SHA-256 of the raw body, compared in constant time).                                                      | `adapters.py`                                                                   |                                                                    |
| The Meta verification handshake requires the verify token, compared in constant time.                                                                                 | `backend/app/api/omnichannel/routes.py`                                         |                                                                    |
| The inbound email endpoint requires `X-Email-Inbound-Secret`. A missing secret or header refuses every request.                                                       | `omnichannel/routes.py` (`_header_secret_matches`)                              |                                                                    |
| Stripe webhooks are verified with `stripe.Webhook.construct_event`, and refused when the webhook secret is empty.                                                     | `backend/app/api/billing/routes.py`                                             | Billing is off in production.                                      |
| Outbound webhook and website fetches use an egress guard. Private and internal addresses are refused, and each fetch is pinned to the address it was checked against. | `backend/app/services/egress_guard.py`, `backend/app/api/knowledge/sources.py`  | `test_webhook_security.py` covers redirects and private addresses. |
| The widget only loads on allowed domains. An empty allow-list denies every host in production.                                                                        | `backend/app/services/widget_service.py` (`domain_allowed`, `domains_required`) | Browser checks are a courtesy. They are not authentication.        |

### Data handling

| Control                                                                                                                                               | Where                                                                          | Notes                                                             |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| API keys and widget session tokens are stored as hashes and compared in constant time.                                                                | `backend/app/services/api_key_service.py`, `backend/app/api/widgets/public.py` |                                                                   |
| OAuth state is a signed token, and its nonce is compared with a hash held in a cookie.                                                                | `backend/app/api/integrations/routes.py`                                       |                                                                   |
| Uploads are stored under `UPLOAD_DIR`. The server refuses a symlinked root and a root not owned by the process user, and creates it with mode `0700`. | `backend/app/services/storage.py`                                              | Ownership on the running volume is **unverified**. See section 2. |
| Brand file serving checks the resolved path stays inside the upload root.                                                                             | `backend/app/api/branding/routes.py`                                           |                                                                   |
| Spreadsheet import refuses macro-enabled and binary workbooks, and checks the file before it reads it.                                                | `backend/app/services/lead_import_service.py`                                  |                                                                   |
| Marketing outreach checks consent, do-not-contact entries, opt-outs, quiet hours and a limit of two attempts a day to one contact.                    | `backend/app/services/outreach_policy.py`                                      |                                                                   |
| Unsubscribe links are signed with HMAC and compared in constant time.                                                                                 | `backend/app/services/marketing/unsubscribe.py`                                |                                                                   |
| Email logging does not write the sign-in code to the log.                                                                                             | `backend/tests/test_email_log_privacy.py`                                      | The test checks the code value is absent from the log output.     |
| Output secret redaction exists as code, through `security_service.redact_output` and `scan_text`.                                                     | `backend/app/services/security_service.py`                                     | It is reached from the operations endpoints only. See section 2.  |

## 2. Accepted risks and open items

Each item says who owns the decision. The owner items are also in `blocker.txt`.

| #   | Risk or gap                                                                                                                                                                                                                             | Why it is accepted or open                                                                                                                                              | Owner or next step                                                                                                                       |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Content Security Policy allows inline scripts.** `Caddyfile` sets `script-src 'self' 'unsafe-inline'`.                                                                                                                                | The TanStack Start streaming bootstrap is inline, and its hash changes with each route and build, so hashes cannot be maintained. The `Caddyfile` comment records this. | Owner to accept. Revisit when the framework supports nonces.                                                                             |
| 2   | **Two CSP headers.** The Caddy policy is for the web app. The API sends a stricter policy for JSON. The repository does not show which header a client receives on each path.                                                           | Both are set, and neither is verified on the running stack.                                                                                                             | Engineering: record the response headers after the first deploy (see [HOSTINGER-DEPLOYMENT](../HOSTINGER-DEPLOYMENT.md), section 9).     |
| 3   | **Sign-in mail is not configured.** `SMTP_HOST` is not set on the server, so no sign-in code is sent. The sign-in request returns HTTP 503, and no user can sign in.                                                                    | No bypass exists. Users are locked out instead of let in.                                                                                                               | Owner: `blocker.txt` item 1.                                                                                                             |
| 4   | **Backups are not configured and not tested.** `weekly_backup.py` exists, but no schedule, destination, passphrase file or restore drill is recorded.                                                                                   | The repository says backup evidence is an external release gate.                                                                                                        | Owner: choose the destination and retention (`blocker.txt`). Engineering: schedule and run one restore drill.                            |
| 5   | **No tested rollback.** Migrations run on start, and no downgrade path is documented.                                                                                                                                                   | See [HOSTINGER-DEPLOYMENT](../HOSTINGER-DEPLOYMENT.md), section 7.                                                                                                      | Engineering, before the first schema-changing release.                                                                                   |
| 6   | **Rate limits fail open for the webhook and general API tiers** when the shared store fails.                                                                                                                                            | By design in the code, only the `auth` and `ai` tiers fail closed. Provider webhooks are not refused during a store outage.                                             | Accepted.                                                                                                                                |
| 7   | **`TRUSTED_PROXY_IPS` is set by hand.** The proxy's address can change when its container is recreated. An entry that covers addresses that clients can connect from lets a client set its own `X-Forwarded-For` and evade rate limits. | Set to the proxy's exact address. The deployment guide explains how to check it.                                                                                        | Engineering: check after each proxy recreation.                                                                                          |
| 8   | **Output redaction is not in the chat reply path.** `redact_output` and `scan_text` are called from the operations endpoints only.                                                                                                      | Model replies are not scanned for secrets by these functions.                                                                                                           | Engineering to confirm whether the reply path needs it. The output must not be described as scanned until it is.                         |
| 9   | **Caddy access logging is off.**                                                                                                                                                                                                        | No request log exists at the edge, so there is less evidence after an incident.                                                                                         | Owner to decide whether logs are kept, and for how long.                                                                                 |
| 10  | **Upload volume ownership is unverified.** A new named volume may be owned by root, and the storage code refuses to start if it is not owned by the process user.                                                                       | The check is in the code. The running volume has not been checked.                                                                                                      | Engineering: run the check in [HOSTINGER-DEPLOYMENT](../HOSTINGER-DEPLOYMENT.md), section 9.                                             |
| 11  | **Host controls are not in the repository.** Firewall, fail2ban, SSH settings and security updates are owner-stated, not verified.                                                                                                      | They are outside the code.                                                                                                                                              | Owner: confirm, using the commands in [HOSTINGER-DEPLOYMENT](../HOSTINGER-DEPLOYMENT.md).                                                |
| 12  | **The README lists development accounts and their passwords.** The accounts are seeded only in development, and the seed script refuses to run elsewhere.                                                                               | Local development convenience.                                                                                                                                          | Engineering: the README should say these accounts must never be seeded on a server. Owner to decide whether the passwords should change. |
| 13  | **No single sign-on.** No SSO, SAML, OIDC or SCIM is built.                                                                                                                                                                             | Planned under Product 9.                                                                                                                                                | See [PRODUCT-PORTFOLIO](../PRODUCT-PORTFOLIO.md).                                                                                        |
| 14  | **No admin log viewer.** Error and audit logs are shown as empty states in the admin area, and no screen downloads them.                                                                                                                | The audit records exist in the backend.                                                                                                                                 | Engineering, listed in `blocker.txt`.                                                                                                    |
| 15  | **Secret-history and dependency scans are not in this review.** They are release gates in [RELEASE-CHECKLIST](RELEASE-CHECKLIST.md).                                                                                                    | Not run for this documentation pass.                                                                                                                                    | Engineering, before a production claim.                                                                                                  |
| 16  | **OAuth client secrets are not in the registry.** Slack, Notion, HubSpot, Google Calendar and Google Sheets secrets are read from the environment but are not in the secret inventory or the console.                                   | They are never returned by an API.                                                                                                                                      | Engineering: add the names to the registry (a code change).                                                                              |

## 3. Reporting a problem

Report a suspected vulnerability privately, as described in [SECURITY.md](../../SECURITY.md).
Do not open a public issue or paste a secret, token or personal data into a ticket.
